# 跨网段摄像头探测（进阶教程）

> 适用：摄像头和 NAS **不在同一个网段**时，TS Safe 控制台显示摄像头「离线」的解决办法。
> 如果你家所有设备都在同一个网段（例如都是 `192.168.8.x`），**你不需要做任何事**，直接忽略本文。

---

## 一、为什么控制台显示「离线」

这不是摄像头坏了，也不是软件问题，而是家庭网络拓扑决定的：

- 摄像头接在运营商光猫下，属于 `192.168.1.x` 网段；
- NAS 接在主路由下，属于 `192.168.8.x` 网段；
- NAS 发往摄像头的包能到达主路由，但摄像头回包时，光猫**不认识** NAS 所在的 `192.168.8.x` 网段，包回不来。

结果：NAS 探不到摄像头，控制台就显示「离线」。

> TS Safe 已经做了「尽力探测」：先 ping，ping 不通再试常见摄像头端口（80/443/554/8080/8000/37777/34567）。只要网络层面能通，就能显示在线；通不了，就诚实显示离线，而不是假装在线或误报故障。

---

## 二、原理（一句话）

让**主路由**对「从 NAS 网段发往摄像头网段」的流量做一次 **源地址转换（SNAT / MASQUERADE）**。

这样摄像头回包先回到主路由（同 `192.168.1.x` 段，光猫认识），再由主路由转给 NAS。**光猫全程无感知，也不需要你有光猫的管理权限。**

NAS 本身不用接任何多余的线，保持现状即可。

---

## 三、操作步骤（以华硕路由器为例）

以下以 **华硕 RT-BE88U（固件 3.0.0.6.x，原厂 AsusWrt）** 为例，其它品牌思路完全一致。

### 1. 开启 SSH 与脚本持久化

1. 登录路由器管理页（通常是 `http://192.168.8.1`）。
2. 进入 **系统管理 → 系统设置**。
3. 设置：
   - **启用 SSH**：`是`（连接方式选 `LAN only` 即可）
   - **启用 JFFS 自定义脚本和配置**：`是`
4. 点击 **应用本页面设置**。

### 2. 登录路由器并先测试规则

用 SSH 客户端连接（Windows 可用 PowerShell 或终端，macOS / Linux 用自带终端）：

```sh
ssh admin@192.168.8.1
```

密码就是你路由器的管理密码。

登录后，**先手动加一条规则测试**（确认有效再固化，免得无效时难排查）：

```sh
iptables -t nat -A POSTROUTING -s 192.168.8.0/24 -d 192.168.1.0/24 -o wan0 -j MASQUERADE
```

参数说明，请按你家真实网段修改：

| 参数 | 含义 | 示例 |
|---|---|---|
| `-s 192.168.8.0/24` | NAS / 电脑所在的网段 | 你家主路由 LAN 段 |
| `-d 192.168.1.0/24` | 摄像头所在的网段 | 你家光猫段 |
| `-o wan0` | 华硕 WAN 接口名 | 若不同，用 `ip addr` 看拿到光猫段 IP 的接口 |

### 3. 在 NAS 上验证

SSH 进 NAS（或用 QTS 终端），执行：

```sh
ping 192.168.1.240     # 换成你摄像头的真实 IP
```

能通 → 说明跨网段探测已打通。回到 TS Safe 控制台，刷新或重新检测该摄像头，就会显示「在线」。

### 4. 固化规则（重启不丢）

确认通了之后，回到路由器 SSH，执行：

```sh
cat > /jffs/scripts/nat-start <<'EOF'
#!/bin/sh
iptables -t nat -A POSTROUTING -s 192.168.8.0/24 -d 192.168.1.0/24 -o wan0 -j MASQUERADE
EOF
chmod +x /jffs/scripts/nat-start
```

路由器每次开机 / 重建 NAT 会自动执行该脚本，规则永久保留。重启路由器后再 `ping` 一次确认即可。

## 四、如果第 3 步 ping 不通，按顺序排查

1. **防火墙拦截 LAN→Intranet**
   路由器 **防火墙 → 一般设置** 里若有「阻止来自局域网的访问到 Intranet / 阻止 LAN 访问 WAN 上的私有网络」之类开关，先关掉；或加一条允许转发：
   ```sh
   iptables -I FORWARD -s 192.168.8.0/24 -d 192.168.1.0/24 -j ACCEPT
   ```

2. **确认主路由 WAN 在摄像头网段**
   路由器 **网络地图 / 外部网络(WAN)** 里查看 WAN IP 是否为 `192.168.1.x`。
   如果不是（例如你是光猫桥接 + 主路由 PPPoE 拨号），WAN 侧没有摄像头网段的直连路由，需要先调整上网方式，本教程不适用。

3. **新固件 nftables 兼容**
   3.0.0.6.x 底层是 nftables，极少数情况下 `iptables` 写的规则不生效。可把 `wan0` 换成实际接口（用 `ip addr` 查看），或改用 `nft` 命令（可联系支持获取对应写法）。

## 五、其它品牌 / 不想动路由器怎么办

- **其它智能路由（OpenWrt / 爱快 / 小米 / 华为企业级等）**：思路一致，在路由器上对「NAS 网段 → 摄像头网段」的流量加 SNAT / MASQUERADE 即可，只是命令与界面不同。
- **不想动路由器**：可以用一对 **电力猫（电力线适配器）** 把光猫的 LAN 口延伸到 NAS 旁边，给 NAS 接第二个网口并配置摄像头网段的静态 IP（**网关留空**）。这样 NAS 与摄像头同处一个二层网络，无需改任何路由器设置。
- **摄像头本身可迁移**：若未来更换为可自行管理的摄像头（如海康 / TP-Link 普通款），直接接在主路由下、与 NAS 同网段，开箱即用，连本文都不需要。

---

## 六、小结

| 情形 | 需要做什么 |
|---|---|
| 摄像头与 NAS 同网段 | 什么都不用做，TS Safe 直接探测在线 |
| 摄像头在光猫独立网段（如本文场景） | 默认显示离线属正常；进阶用户按本文在主路由加一条 SNAT 规则即可看到在线 |
| 完全不想碰路由器 | 用电力猫延伸光猫 LAN 到 NAS 旁，或换可自管网段的摄像头 |
