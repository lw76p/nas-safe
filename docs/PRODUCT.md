# NAS Safe — 产品决策文档

> 版本：v1.0　定稿日期：2026-09-29
> 本文档固定产品决策，后续开发以此为准，不再反复讨论。

---

## 一、一句话定位

**给 NAS 上的一把锁和一个傻瓜时间轴——装完默认开启，出事一键回滚。**

- 主定位：**防勒索层**（快照之上的锁 + 篡改告警 + 异地不可变副本）
- 副定位：顺手做空间清理、硬盘监控、体检报告（引流用）
- **不是**：快照工具、NAS 全能工具箱、备份软件

### 为什么不是"快照工具"

各家系统自带快照（飞牛、绿联、群晖、威联通、TrueNAS 全都有），做"又一个快照管理"没有生存空间。真正的空白在于：

1. **各家快照能被管理员删除** —— 绿联官方文档明确承认 "Locked snapshots also remain manageable by an administrator, so they are not immutable recovery copies"。勒索攻击的标准动作就是先删备份再加密生产数据。
2. **各家只管家门口** —— 多台设备各自为战，没有统一视图。
3. **各家都要用户自己配置** —— 普通用户根本不去开。

### 产品定位一句话卖给用户

> **"你的快照，勒索软件能删。我们把它锁住。"**

营销第一步是先建立"快照会被删"的认知，而不是卖"漂亮界面"。

## 二、竞品分析结论

| 竞品 | 做了什么 | 短板 | 我们的对策 |
|---|---|---|---|
| **httm**（Rust 开源） | 文件级 Time Machine，支持 ZFS/btrfs/nilfs2，能找回已删文件，跨数据集搜索 | **纯命令行 TUI**，小白打不开就关 | **直接复用 httm 当后端**，我们做 Web UI |
| **各家系统自带快照** | 快照创建、计划、保留策略、整卷/文件夹回滚 | 无好用的单文件取回；管理员能删；只管本机；默认不开 | 锁快照 + 篡改检测 + 跨品牌 + 默认开启 |
| **Restic / Borg / Kopia / Duplicati** | 加密去重备份到对象存储 | 命令行、无 GUI、要用户自己配目标 | 定位不同，不冲突；可作为异地副本的目标之一 |
| **Veeam / Acronis** | 企业级，带不可变 | 贵、重、面向企业 IT | 我们做"小而傻瓜"的个人版 |

### 产业共识：防勒索三层防御

1. **不可变**（WORM / immutable snapshot）— 防删除、防加密
2. **气隙隔离**（物理/逻辑分离）— 防网络蔓延
3. **凭据分离**（独立认证）— 防凭据被盗

**关键事实（来自专业资料）：** 现代勒索攻击会先攻击备份系统。攻击链是：入侵 → 横移 → 找备份凭据 → 攻陷备份系统 → **删掉备份** → 最后加密生产数据。攻击到加密之间往往间隔数周，攻击者有充足时间清空所有可达的备份。

**ZFS 的 `hold` 也不是真不可变** —— 攻击者有 root 可以 `zfs release` 再 `zfs destroy`。真正的不可变必须复制到一个攻击者碰不到的系统。

## 三、目标系统与适配优先级

### 首发覆盖（v1.0）

| 系统 | 文件系统 | 适配方式 | 优先级 |
|---|---|---|---|
| **飞牛 fnOS** | btrfs（默认） | Debian 底子，SSH 开放，Docker 现成 → 直接调 btrfs | **P0 · 首发** |
| **裸 Linux** | btrfs / ZFS | 直接调命令 | **P0** |
| **TrueNAS** | ZFS | 直接调 zfs 命令 | **P0** |
| **Unraid** | btrfs / ZFS（部分） | 直接调命令 | **P0** |
| **OMV (OpenMediaVault)** | btrfs / ZFS | Debian 底子，直接调命令 | **P0** |
| **绿联 UGOS Pro** | **建池时二选一：ext4 / Btrfs** | SSH 开放程度待实测；快照仅 btrfs 存储空间支持 | **P1** |
| **群晖 DSM（开 SSH）** | ext4 默认 / Btrfs 看型号 | btrfs 机型可走命令；ext4 机型走 API | **P1** |
| **威联通 QTS** | **ext4 + 块级存储池快照**（非 btrfs；QuTS Hero 才是 ZFS） | **B 类官方 Snapshot API**（见 docs/QNAP-REALITY.md 真机实测） | **P1** |

### 暂不支持

- 极空间等无 SSH、无 btrfs、无开放接口的封闭系统 —— 强做只会做出空壳

### 适配架构设计

**一套 Linux 通用内核 + 薄薄的品牌适配壳。** 飞牛/绿联/OMV 都是 Debian + btrfs + Docker，代码复用率极高。

适配层分级：

- **A 类·干净环境**（飞牛、裸 Linux、TrueNAS、Unraid、OMV）→ 直接调 `btrfs` / `zfs` 命令
- **B 类·Web API / 块级快照**（群晖 DSM、威联通 QTS）→ 调官方 API。注意 **QTS 标准版是 ext4 + 块级存储池快照，没有 btrfs 命令**，实测见 docs/QNAP-REALITY.md
- **C 类·封闭系统** → 暂不支持

### 绿联的两个关键未知量（需实测）

1. SSH 是否开放、能否 root
2. 快照在系统里的挂载路径 —— 是标准 btrfs 子卷还是绿联自定义路径

**绿联用户分两类：**
- Btrfs 池 → 可直接支持
- Ext4 池 → 无法快照，只能"检测 + 引导重建为 btrfs"（这个检测能力本身就是差异点，绿联界面不会主动提醒用户选错了文件系统）

## 四、功能梯次

### v1.0 — 飞牛 + P0 系统 MVP

**只做三个功能：**

1. **存储池体检**（顺带发现"没开快照"）
   - 角色：引流钩子
   - 输出：图文报告，红黄绿标识
2. **时间轴快照管理**（拍/看/取文件/回滚）
   - 角色：核心，主角
   - 单文件取回建议复用 httm
3. **重复文件扫描**（附带赠送）
   - 角色：立刻见效的"哇感"

**用户装完的购买理由：能省空间、能找文件、能救命。**

### v2.0 — 防勒索深化 + 商业化

- 快照锁定（独立权限账户持有）
- 篡改检测 + 完整性校验
- 服务号 / 群机器人告警（温度、SMART、快照异常）
- 硬盘 SMART 预警
- 异地副本（用户自己的对象存储：阿里云 OSS / 腾讯云 COS / Backblaze B2 / CF R2）
- 多设备统一看板

### v3.0 — 高级能力

- 更多品牌适配（群晖、威联通）
- AI 功能（人话翻译、自然语言搜文件、规则建议）
- 勒索行为检测（扩展名突变 / 熵值升高 / 大量重命名 → 自动紧急快照 + 告警）
- 攻击复盘报告（企业版杀手锏）
- 移动硬盘冷备（拔了就走，防勒索最狠的一招）

### 明确不做

- 一键部署常用服务（那是 DeployEasy 的事，别混）
- 数据恢复服务（成功率不可控，口碑风险大；定位是"防患于未然"，不是"事后抢救"）
- 大而全的工具箱（会毁掉防勒索定位）

## 五、AI 功能的定位

**AI 是"翻译官 + 检索员 + 提案人"，不是"决策者"。**

| 用 AI ✅ | 不用 AI ❌ |
|---|---|
| 把 SMART/btrfs/ZFS 数据翻译成人话 | 判断"这是不是勒索攻击"（规则引擎更准、更快、可解释） |
| 自然语言找文件（"上个月和装修公司签的合同"） | 自动执行恢复（人命关天，必须人工确认） |
| 生成体检报告的"人话版"结论 | 自动操作文件（AI 只提议，用户确认，程序执行） |
| 提议整理规则（用户确认后执行） | |

### 技术选型与三个坑

**坑一：模型放哪**
- 默认上云（通义/DeepSeek/智谱），但**给用户开关，可完全关闭**
- 本地模型（Ollama + Qwen）作为可选，需较强硬件
- **核心功能绝不能依赖 AI** —— 拔网线、API 挂了、用户不付钱，产品都要完整可用

**坑二：成本**
- AI 全部放付费版
- 调用频率限制（体检报告每天 ≤3 次，语义搜索每天 ≤50 次）

**坑三：别做成必需依赖**
- AI 是"锦上添花"，不是"地基"
- 与"核心必须离线可用"是同一原则

## 六、商业模式与定价

### 核心原则

**不能卖"功能"，要卖"安心"和"省事"。** 快照是系统白送的原料，收不了"快照钱"；用户愿意付费是因为"我不用管、出事能救回来"。

### 定价结构（买断制）

| 版本 | 价格 | 包含 |
|---|---|---|
| **免费版** | ¥0 | 核心引擎 + 时间轴 UI + 单文件取回 + 一键回滚 + 空间清理 + 基础体检（**全功能不限量**） |
| **进阶版** | **¥69 买断** | v1.x 全部功能 + v1.x 所有更新 |
| **进阶版 Pro** | **¥99 买断**（主推） | v1.x + 未来所有大版本免费升级 |
| **企业版** | 按台议价 | 集中管理、审计日志、权限分级、双人复核、SLA |

**主推 ¥99**（价格锚定：¥69 与 ¥99 差 30 元但更新年限差很多，大部分人选 ¥99）。

### 免费版必须"够用"

免费版要给到"能自救"的程度——时间轴、手动拍快照、单文件取回、整卷回滚全免费。因为：
1. 免费版是最好的广告（用户真救回一次数据 → 主动发帖传播）
2. 收费点放在"用户自己做不到的事"上

### 核心洞察

- 免费版解决"我今天不小心删了文件" → 日常小确幸 → 用户感谢你
- 付费版解决"我中了勒索/家里出事了" → 生死攸关 → 用户掏钱

### 价格锚定话术

> 一次数据恢复服务的市场价是 ¥2000+，而它只需要 ¥99，且永久有效。
> 你手机里随便一张照片，花 ¥99 都找不回来。

### 进阶版包含

- 自动快照策略（每小时 / 每天 / 智能）
- 快照锁定 + 篡改检测告警
- 异地不可变副本（同步到用户自己的云存储）
- 多设备统一时间轴看板
- 一键体检报告（含 AI 人话解读）
- AI 功能（语义搜索、规则建议）

### 假设被拒绝的方案

- **不做 OEM 授权卖给飞牛/绿联** — 个人开发者没有对接渠道，且对方自己会做、采购流程个人过不了、周期一年起步，与"恢复现金流"背道而驰
- **不做年费订阅** — NAS 用户对订阅有心理创伤；且核心功能零持续成本，收年费在良知上站不住

### 三条变现线同时挂

1. ¥69 / ¥99 买断（主力）
2. 远程代部署服务 ¥100-300 一次（小白不会装，用户不抵触服务收费）
3. 企业版按台议价（撑价格体系 + 后期利润空间）

## 七、更新策略

**用"版本制"代替"年限制"。**

- ¥69 买断 = 永久使用 v1.x + v1.x 所有小版本更新
- ¥99 买断 = v1.x + 未来所有大版本免费升级
- 将来出 v2.0（如勒索行为检测），想要的话再付升级费

理由：比"三年更新"更诚实，更容易长期维持（涛哥还有 DeployEasy、HMP、宠物洗护站，不可能三年高强度投入）。

### 更新内容清单（真会做的，非画饼）

1. **新增系统适配** — 飞牛/绿联 → 群晖/威联通/TrueNAS/Unraid/OMV
2. **告警渠道扩展** — 群机器人 → Bark/ntfy → Web Push
3. **异地备份目标扩展** — 更多云盘、NAS 对 NAS、移动硬盘冷备
4. **防勒索能力深化** — 行为检测、完整性校验、异动审计、一键救援模式
5. **系统升级兼容修复** — NAS 固件更新后的适配（**这条最值钱**，用户最怕"系统一升级软件就废了"）

### 节奏承诺

"持续更新，重大功能里程碑发布" —— 不给"每月更新"这类硬指标。

## 八、技术与合规架构

### 三链路分离

| 链路 | 方案 | 合规要求 |
|---|---|---|
| **① 收款** | 微信小程序内微信支付（优先）；服务号内支付 | **不需 ICP 经营许可**（卖软件 ≠ 运营互联网信息服务平台） |
| **② 推送** | 服务器 IP 直连服务号模板消息 API | **不需域名、不需备案**（只需 IP 白名单） |
| **③ 分发** | Docker 镜像（腾讯云 TCR / 阿里云 ACR）+ GitHub/Gitee 开源 | **不需境内网站** |
| **④ 使用** | NAS 本地 Web 界面（局域网访问） | 不对外提供互联网服务 |
| **⑤ 升级** | License 文件离线签名验签 | 不依赖服务器存活 |

### 备案问题

- **推送（模板消息）不需要域名备案** —— 服务端到服务端，不涉及网页
- **收款走小程序** —— 微信生态内交易，不需要域名
- **网页授权、内嵌网页、支付跳转** —— 这些要备案，**用"6 位绑定码"和"小程序"完全替代**

### 合规边界

**需要办 ICP 经营许可证的对象是：自建境内域名、面向公众注册、按年订阅收服务费的"云平台"。** 我们不是这个。

我们卖的是**软件使用许可（一次性买断）**，本质是"卖软件"，不是"运营互联网信息服务平台"。

### 必须避开的红线

- 不要自建境内域名、面向公众注册、按年订阅收服务费的云平台
- 不要做明显的规避动作（境外主体、不留联系方式）
- 企业客户要发票 → 接第一个企业单时再注册个体户

### 免责说明

以上为基于公开规则的判断，非法律意见。体量小时不必焦虑；若年收入几十万以上，花几千块咨询专业财税/法律。

## 九、告警渠道设计

**邮件在国内这个场景是死路** —— NAS 告警邮件发不出去（家用宽带封 25 端口）、邮箱没人天天看、勒索软件会清理邮件客户端。

### 渠道优先级

| 层级 | 渠道 | 门槛 | 定位 |
|---|---|---|---|
| **A 类·零门槛** | 企业微信 / 飞书 / 钉钉群机器人 | 粘一条 Webhook URL | **免费版就给** |
| **B 类·进阶核心** | **微信服务号模板消息** | 用户关注服务号 | **付费版核心卖点** |
| **C 类·极客向** | Bark / ntfy | 装个 App | 顺带支持 |
| **D 类·补充** | 邮件 | 配 SMTP | 可选，默认关 |

**关键洞察：** 企业微信/飞书/钉钉的"群机器人"是这三家唯一不需要企业资质、不需要审批、个人一条 Webhook 就能用的推送通道。群消息有红点和声音，能真正叫醒人。

### 模板消息的前提

**必须用户和服务号有交互记录**（关注过 / 支付过）才能推送。所以流程设计：

1. 用户购买时引导关注服务号（付款后弹"关注服务号，快照异常第一时间通知你"）
2. 之后所有告警通过服务号推送

### 必须做的产品细节

**安装引导里跑一次"测试推送"** —— 用户填 Webhook → 点"发送测试消息" → 手机收到红点 → 信任建立。

这一步不做，用户永远不知道自己配没配对。

## 十、信任模型（最关键的一条）

### 为什么必须开源

**用户要交出系统最高权限、要让我们读他全部数据。** 闭源 = 用户不敢装 = 直接判死。

DeployEasy / HMP 可以闭源（它们不碰用户全盘数据），但防勒索工具不行。

### 分层授权设计

| 部分 | 授权方式 |
|---|---|
| **核心功能** | **完全不校验**。开源代码，谁都能跑，哪怕没有 license |
| **进阶功能** | **本地 License 文件校验**（离线 RSA/Ed25519 签名，**不联网激活**） |

**关键：License 是离线签名的文件，不是联网激活。**

好处：
1. **永不失效** — 服务器关了，已买的 license 照样能用（买断制的核心承诺）
2. **零运维成本** — 不需要激活服务器
3. **一机一码可做但不怕破解** — license 写入机器指纹，即使被破解也无所谓（核心功能本来就免费，损失的只是进阶功能）

**核心功能必须做到"拔网线也能救数据"。** 用户装防勒索软件是为了在"最坏的时候"能救回来；如果这个工具本身依赖单点服务器活着，那保护了什么？

### 这条也是营销素材

开源 = 解决"用户凭什么信你"。而且**你还有一个认证服务号 + 微信支付交易记录 + 品牌形象** —— 用户点进去一看，不是匿名 GitHub 项目，是个真人在认真做。

**一个服务号 = 官网 + 客服 + 推送 + 收银台。**

| 小程序开发能力（宠物洗护站） | 收款小程序 |
| Debian/Linux + btrfs + Docker 经验 | 核心引擎 |

**唯一的约束：域名没备案（用 CF 免费服务）。** 但这恰好与"本地优先"的产品设计天然吻合。

## 十二、技术架构

### 交付形态

**不是"又一个 NAS 套件"，而是"装在 NAS 上的一个常驻容器 + 一个 Web 界面"。**

```
用户操作 → Web UI（浏览器）
              ↓ HTTP (localhost:PORT)
         后端服务（容器内）
              ↓ 调用命令
    btrfs / zfs / httm 命令
              ↓
        底层存储
```

### 为什么用 Docker

1. **绕开各家应用商店** —— 群晖 SPK、威联通 QPKG 打包体系完全不同，做两套会疯
2. 容器只需 `--privileged` + 挂载宿主机路径，即可操作宿主机存储
3. 支持远程纳管（未来）

### 技术栈建议

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | **Python (FastAPI)** 或 Node | Python 处理系统命令和数据处理方便；Node 与现有项目一致 |
| 前端 | 原生 HTML/CSS/JS 或轻量框架 | 复用小程序/Web 经验；时间轴 UI 需要自定义 |
| 快照操作 | 直接调 `btrfs` / `zfs` 命令 | 标准命令，跨品牌通用 |
| 单文件取回 | **复用 httm**（MPL 2.0，可商用） | 功能已完备，含已删除文件考古 |
| 打包 | Docker + 多仓库推送 | 复用 DeployEasy 流水线 |

### 关键风险

**容器内做快照需要访问宿主机 pool。** 群晖/威联通存储架构封装较深，需实测验证。飞牛/裸 Linux/OMV 无障碍。
