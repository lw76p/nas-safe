# 没有真实 NAS 硬件，怎么实测（虚拟机方案）

结论：**除绿联外，所有目标系统都能在虚拟机里免费实测。**
你不需要为了这个软件买任何硬件。而且核心逻辑（容器在 btrfs/ZFS 上干活）
用一个裸 Linux 虚拟机就能验证 90%，连飞牛都不用装。

---

## 一、核心洞察：你验证的是什么

我们的产品本质 = **在宿主机上跑一个特权容器，容器调 btrfs/zfs 命令操作快照**。

所以"真机 vs 虚拟机"对我们要验证的东西**几乎无差别**：

| 要验证的能力 | 虚拟机能验吗 | 说明 |
|---|---|---|
| 探测文件系统 / btrfs / zfs 命令可用性 | ✅ 完全等价 | 虚拟机里就有真实 btrfs |
| 容器特权模式访问宿主机存储 | ✅ 完全等价 | 容器挂的是虚拟机的 `/`，btrfs 就在里面 |
| 拍快照 / 列快照 / 浏览 / 取回 / 回滚 | ✅ 完全等价 | 操作的是真实文件系统 |
| 品牌特有路径（如飞牛 `/vol1` 布局） | ⚠️ 需装该系统 | 只有这层需要对应系统 |
| SSH 开放情况 / 权限模型 | ⚠️ 需装该系统 | 同上 |

**所以策略是：先用裸 Linux 把核心逻辑跑通，再用飞牛/群晖虚拟机补"品牌层"。**

---

## 二、分层验证路线图

### 第一层：裸 Linux + btrfs（今天就能做，零系统安装成本）

目标：验证容器在 btrfs 上能完整干活。

```
1. 装虚拟机软件：VirtualBox（免费，https://www.virtualbox.org）
2. 新建 VM：Debian 12，2 核 / 2G 内存 / 20G 虚拟磁盘
3. 安装 Debian（最小化即可）
4. 进系统：
   apt update && apt install -y btrfs-progs docker.io
5. 造一个 btrfs 测试卷（用 loop 文件，不用真硬盘）：
   truncate -s 10G /btrfs_test.img
   mkfs.btrfs /btrfs_test.img
   mkdir -p /mnt/btrfsvol
   mount -o loop /btrfs_test.img /mnt/btrfsvol
6. 跑我们的容器（挂载宿主根，特权模式）：
   docker run -d --privileged -v /:/host:ro -p 8848:8848 tsetch/nas-safe
   # 或本地源码跑：NASSAFE_WEB_DIR=./web python3 server/app.py
7. 浏览器开 http://虚拟机IP:8848 → 应该能看到存储单元和"拍快照"按钮
8. 跑探测脚本：sh scripts/probe.sh
```

**验证通过的标准**：probe.sh 识别到 btrfs、能列命令；界面能创建快照、
能浏览、能取回文件、生产数据不被覆盖。

### 第二层：飞牛 fnOS 虚拟机（官方 ISO，免费，最接近真机）

飞牛官方支持虚拟机安装，有公开 ISO，这是**首发目标的必测项**。

```
1. 下载 ISO：https://fnnas.com/  → 当前版本 fnos-0.9.9-937.iso
2. VirtualBox / VMware / PVE / ESXi 新建 VM：
   - 磁盘：系统盘 64G（飞牛建议），另加一块数据盘（如 100G）做存储池
   - 内存 2G 起，CPU 2 核起
   - 注意：UEFI 安装需关闭 Secure Boot
3. 安装 fnOS → 设置管理员 → 进 Web UI
4. 创建存储空间（选 btrfs）→ 得到存储单元
5. 飞牛设置里开启 SSH
6. SSH 进去跑：sh scripts/probe.sh  → 拿到飞牛的真实路径/权限数据
7. 把容器跑起来（飞牛自带 Docker）→ 验证飞牛特有路径
```

### 第三层：群晖（黑群晖 XPEnology，免费但非官方）

用于验证"开了 SSH 的群晖"适配路径。注意黑群晖**仅测试用**，别当生产。

```
1. 用 ARPL 或 ARC 引导镜像（GitHub 开源引导器）
2. VMware Workstation / VirtualBox 新建 VM：
   - 引导盘：ARPL/ARC 的 img 转 vmdk 挂上
   - 数据盘：新建一块虚拟磁盘（100G），独立不要混用
   - 网络：桥接模式（NAT 搜不到设备）
3. 启动 → 浏览器访问 find.synology.com → 安装 DSM 7.x
4. 控制面板开启 SSH
5. SSH 进去跑 probe.sh
```

> 风险提示：黑群晖版本敏感，引导与系统 PAT 文件必须匹配；别开自动更新（可能破坏引导）。
> 仅用于适配验证，不要长期使用。

### 第四层：绿联 —— 虚拟机装不了，怎么办

**UGOS Pro 是闭源固件，没有公开 ISO，无法在虚拟机装。**

但绿联的底层和飞牛一样（Debian + btrfs），所以**代码层面的风险很小**——
我们担心的只有"绿联的快照应用占用的路径、SSH 是否开放、btrfs 子卷布局"这几点，
而这几点只能靠真机确认。

绿联的实测方案（三选一，按优先级）：

1. **你手头那台跑 HMP / MoviePilot 的 NAS 如果是绿联** → 直接 SSH 跑 probe.sh（几秒、只读、零风险）
2. **找绿联用户/群友帮跑 probe.sh** → 就一个只读脚本，发过去让人跑一下把输出贴回来
3. **绿联优先级本就靠后**（PRODUCT.md 里标的是"实测中"）→ 先用飞牛/裸 Linux 把核心做扎实，绿联等真机数据再补

## 三、一个重要提醒：你手头可能已经有测试机

你 NAS（192.168.8.62）上跑着 HMP / MoviePilot / RomM。

**如果那台是群晖或威联通，且开了 SSH —— 直接 SSH 进去跑 probe.sh 就测了，连虚拟机都省。**

先确认一下：那台 NAS 是什么系统？如果是群晖/威联通（开了 SSH），
它就是现成的测试环境，比虚拟机还真实。

---

## 四、为什么虚拟机够用，真机不是必须

| 担心 | 虚拟机能否覆盖 |
|---|---|
| "容器在真实 btrfs 上能不能干活" | ✅ 虚拟机里就是真实 btrfs |
| "特权模式挂宿主机根能不能访问存储" | ✅ 挂的是虚拟机根，等价 |
| "时间轴 UI 交互顺不顺" | ✅ 浏览器访问虚拟机 IP 即可 |
| "飞牛特有路径/权限" | ⚠️ 需飞牛虚拟机或真机 |
| "绿联特有路径" | ❌ 需绿联真机或合作 |

**一句话：先用 VirtualBox + Debian + btrfs 把核心跑通（今天就能做），
再用飞牛 ISO 补品牌层，绿联靠真机/合作最后补。你不需要买任何设备。**
