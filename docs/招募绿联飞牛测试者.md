## 二、给测试者的照做步骤（可单独发，更详细版）

### 第 1 步：在 NAS 上开 SSH

- **绿联 UGOS Pro**：设置 → 网络 / 终端 → 开启 SSH（记下 NAS 的局域网 IP 和登录账号）
- **飞牛 fnOS**：设置里 SSH 默认已开启（同样记下 IP 和账号）

### 第 2 步：从电脑连到 NAS

Windows 10 / 11 自带 `ssh`，打开 PowerShell 或终端输入：

```bash
ssh 你的用户名@NAS的IP
# 例：ssh admin@192.168.1.50
```

首次连接会提示 `Are you sure you want to continue (yes/no)?`，输入 `yes` 回车，再输密码。

### 第 3 步：运行探测脚本（不用先下载）

连上后直接粘贴这一行并回车：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/lw76p/nas-safe/main/scripts/probe.sh)
```

> 如果系统没有 `curl`，用这个备选：
> `wget -qO- https://raw.githubusercontent.com/lw76p/nas-safe/main/scripts/probe.sh | bash`

### 第 4 步：把结果发回来

终端会打印一整份"系统探测报告"。**全选复制**（或截图）发给招募的人即可。

## 三、测试者最关心的：安全吗？

- 脚本是**纯只读**的：只读取系统信息（文件系统类型、命令是否存在、权限），
  **不创建快照、不修改、不删除任何文件**。
- 脚本全程开源透明，任何人都能在仓库 `scripts/probe.sh` 看到每一行在干什么。
- 不会读取你的照片 / 视频内容，只报告磁盘的"文件系统类型"这类元信息。

## 四、开发者拿到报告后看什么

| 报告章节 | 绿联 / 飞牛重点关注 |
|---|---|
| 【1】品牌特征文件 | 应出现 `[有] /etc/ugos-release`（绿联）或 `/etc/fnos-release`（飞牛） |
| 【1】判定品牌 | 绿联部分机型/版本可能显示“裸 Linux”，关键看 [4] 挂载点 |
| 【4】挂载点文件系统 | **btrfs / zfs** → 快照可用；**只有 ext4** → 不可用，需重建存储池为 btrfs |
| 【3】关键命令 | 看有没有 `btrfs` / `zfs`（有命令≠有文件系统） |
| 【8】权限 | 是否 root / 有无 sudo（决定后续要不要提权） |
| 【10】适配建议 | 已根据实际文件系统 presence 给出：有 btrfs 给“可适配”，全 ext4 给“需重建存储池” |

判定逻辑：只要数据盘是 btrfs 或 zfs，NAS Safe 的主线方案就能用；
ext4 池（绿联建池时选了 ext4）暂时用不了——这点系统自己不会告诉你，probe 会暴露。

拿到 btrfs 存在的报告后，下一步就是为该系统写适配层（参考已真机验证的威联通 qcli 适配）。

## 五、常见问题（根据第一批反馈补充）

### Q1：报告顶部品牌判定为“裸 Linux”，但实际是绿联 NAS，正常吗？

**正常。** 绿联某些固件/机型没有 `/etc/ugos-release` 这个特征文件，probe 会 fallback 到“裸 Linux”。
只要 [4] 挂载点里出现 `/volume1`、`/volume2` 或设备名带 `ug_`（如 `/dev/mapper/ug_...`），就是绿联 NAS。
最新版 probe.sh 已自动根据这些特征把品牌修正为“绿联 UGOS Pro”。

### Q2：为什么 btrfs 命令“有”，但适配建议还是说“暂不可用”？

**命令存在 ≠ 文件系统存在。** 绿联系统里预装了 `btrfs-progs`，但你的数据盘格式是 ext4，`btrfs` 命令就没事可做。
NAS Safe 快照依赖的是**底层文件系统类型**，不是命令是否存在。必需数据盘为 btrfs/zfs 才能创建快照。

### Q3：绿联只有 ext4，想用 NAS Safe 怎么办？

唯一办法：**备份数据 → 删除现有 ext4 存储池 → 重新创建时选 btrfs。** 重建会清空该池数据，务必先备份。
